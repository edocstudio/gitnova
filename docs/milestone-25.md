# Milestone 25 — Discard during a pending operation

The user had unstaged a merge result, leaving 136 working files, but the operation inspector did not expose the ordinary discard control. Reuse its heading and existing discard review: the trash action selects changed files, offers unstaged-only or selected staged-and-unstaged scope, previews exact paths, and requires confirmation. A notice distinguishes discarding files from aborting the operation. The existing Abort workflow remains separate. No new screen or navigation is introduced; ADR 0022 records the boundary.

Operation-specific commands require the current owned session token, unchanged native operation metadata and no unresolved conflicts. Normal discard still refuses active operations. The common guarded discard engine preserves branch/HEAD and native metadata. Unstaged-only preserves index bytes; selected full scope restores those index/working entries to HEAD. New selected leaves are individually removed after recovery; no recursive clean/reset runs. Receipts retain the recovery folder and pending operation state so the UI remains in the same merge after discard.

Large regular working files in this explicit context use streaming SHA-256 and raw private recovery rather than in-memory content buffers. Limits are 256 MiB per regular working file and 2 GiB of selected working content; staged blob capture retains its existing 16 MiB bound and ordinary discard keeps its prior budgets. Thus large newly untracked files after Unstage can be discarded with complete recovery. All selected backups and manifests finish before the first working-file write. Failures never trigger automatic rollback/retry. Directories, gitlinks, hidden entries, conflicts and unowned operations remain refused. Rapid preview changes queue one request and skip obsolete queued scopes.

Verification is run serially with one compiler/browser worker and temporary repositories only. New core scenarios cover preserved staging/native metadata, selective/full discard, stale session/content rejection, a 20 MiB working binary with raw recovery, and conflict/unowned-operation refusal. The existing 14 discard integration cases also passed. Twenty frontend unit/catalog tests and TypeScript/Vite build passed. Browser workflows passed ordinary discard with persisted recovery and operation discard (review, Cancel, EN/TH, confirmation, raw recovery, unchanged HEAD/MERGE_HEAD and retained inspector). Strict focused core Clippy and workspace formatting passed. The native command-dispatch test passed for the operation-scoped argument contract and remote-origin refusal. GitNova Updated.app built successfully (57.05 MiB), with signature and embedded-asset checks passing. No new native GUI smoke was launched while the user application was running; that live process was not stopped or replaced.
