# ADR 0023 — Discard progress and bounded batching

The existing discard review is the natural place to show waiting and phase progress. Add an inline status/progressbar there, preserving the graph and file scope; no new panel, dialog or navigation. Percentages apply only to a measured phase (checked/backed-up/discarded files or streamed bytes), never an invented overall percentage. Waiting for locks/refresh shows an indeterminate indicator and phase text. Progress is advisory and never authorizes a write or changes its receipt.

A native-independent scoped callback emits typed phase counters from the Git worker. Tauri forwards them over a per-request Channel; no polling/journal writes or Tauri types enter core/Git. Late preview callbacks are ignored. UI callback failures do not change Git outcomes. Native delivery is throttled and the browser test transport forwards real core events.

A controlled temporary owned-merge fixture with 24 small untracked files measured 98 Git launches / 5.404s for preview and 1121 launches / 67.418s for apply (instrumented process wrapper). The repeated per-path ls-files/state/config/ls-tree calls are the primary implementation bottleneck in this fixture. Batch index flags/entries and HEAD membership. The no-checkout fast path for exclusively untracked leaves uses native index/HEAD/branch locks, direct filesystem guards per leaf and full Git/config validation before/after, with raw recovery and byte revalidation retained. Tracked restores retain their per-file Git checks because configured checkout filters may run. Do not infer the cause of earlier host freezes from this benchmark.
