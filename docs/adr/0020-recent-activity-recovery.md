# ADR 0020 — Recorded activity and recovery after restart

Receipts already exist durably, but in-memory feedback disappears at restart. Staging, discard and unsuccessful operations are not commits, so adding them as synthetic history nodes would obscure the graph. Reuse a collapsed Recent activity & recovery section in the existing Working changes inspector; no new screen, permanent panel or navigation. Display historical status/time, checkout identity and recorded recovery pointers. Read-only copy actions do not replay operations, remove locks, claim a backup is complete, or imply current HEAD matches an old receipt.

A Tauri-independent core read API reads only its app-private operation directory. It validates UUID receipt names, ignores symlinks, caps directory enumeration/candidate metadata, reads at most 128 bounded receipt files and 16 MiB total, scopes records to the selected RepositoryId, and returns at most ten summaries. Include linked checkout identities. Missing history is empty; malformed, oversized or omitted records produce explicit incomplete coverage. Never follow recovery paths while listing. Read when the existing section is expanded or refreshed after an operation, not on every status poll. Full original receipts remain unchanged on disk. Unconfirmed started/unknown records remain unconfirmed; there is no automatic retry, cleanup or rollback.
