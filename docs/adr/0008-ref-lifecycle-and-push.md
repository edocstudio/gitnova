# ADR 0008: Recoverable ref lifecycle and explicit single-branch publication

Accepted, 2026-10-25. Extend the graph's existing transient action context; add no permanent navigation or dashboard. Keep configuration changes distinct from checkout and publication.

Branch rename delegates to native no-force `branch -m`, preserving config/reflog, with worktree occupancy and before/after validation. Ref/config snapshots bind the preview to the reviewed state. External Git can still race after validation; postconditions report uncertainty rather than claiming a transaction across refs, config and external programs.

Local deletion uses a native no-dereference `update-ref --stdin` transaction: create or verify a deterministic recovery ref, then delete the exact expected source OID. Current and other-worktree branches are protected. Annotated tags retain their original tag object, not just a peeled commit. Recovery collisions and symbolic refs stop deletion. The local ref transaction is distinct from later local branch-config cleanup; cleanup failure can leave a completed deletion and is reported with its recovery location. Internal recovery refs are retained for GC reachability but excluded from ordinary graph refs/history roots and publication. Automatic expiry and a dedicated restore/config recovery UI remain deferred; never delete recovery refs automatically.

Upstream configuration targets a fetched configured remote ref and does not implicitly integrate or publish. Incompatible worktree-specific branch settings require separate review. The selected remote and merge ref are written explicitly, so another remote with an overlapping fetch mapping cannot change the requested tracking identity. Tracking inherited from includes/global config and forced duplicate branch checkouts are blocked for shared metadata changes. Settings changes retain HEAD/index and native locks. Operation receipts keep actual repo/worktree/membership identities and the full reviewed action. Partial deletion failures include the recovery location in visible recovery guidance; repository result feedback can copy that location for inspection.

Push preview explicitly checks one live push URL. URL resolution must be stable under rewrites. Embedded HTTP credentials/query parameters are rejected before transport invocation; use credential helpers or SSH agents, so URL secrets are not passed as process arguments. Destination presentation/journal data is redacted, and only file/http/https/ssh/git transports are allowed. Credentials/SSH can run for the explicit network check; pre-push hooks do not. The read is bounded by a process-group timeout and output deadline. Offline inspection still rejects all transports. A local destination resolving to the selected common Git directory is blocked, including file URLs, to prevent a push from unexpectedly updating the open worktree.

Only an exact selected local branch/OID is publishable. The destination must be new or an ancestor of that source with all necessary objects available locally. Review shows the complete outgoing commit list (at most 500), destination OID and source OID. Apply reinspects the destination and validates the token, then invokes native push with an explicit immutable OID refspec, no force/lease/mirror/follow-tags and submodule availability checks. It does not publish submodule repositories. A server race is still governed by native non-force/reference checks; no remote/local atomicity is claimed. Configured push hooks/signing run only during confirmed publication.

Cached remote refs update only for a single supported standard fetch mapping whose fetch and push URLs match. The cached update uses the expected prior OID; optional upstream configuration is explicit and separately verified. Push can succeed remotely while cache/configuration fails locally. Receipts must say publication may already exist, preserve the selected target and direct inspection before retrying. No automatic rollback/retry or deletion is attempted.

Tests use temporary repositories and local bare remotes, including hook-induced destination races and post-publication config failure. A controlled SSH helper fixture checks timeout behavior without external network access. This is not native cross-platform or release certification.

References: [native branch rename/upstream behavior](https://git-scm.com/docs/git-branch), [expected-OID ref transactions](https://git-scm.com/docs/git-update-ref), [native push rules and hooks](https://git-scm.com/docs/git-push).

Transport uses an explicit destination URL and pinned source OID rather than implicit push defaults. Hooks therefore receive native explicit-URL/OID arguments; remote-name-specific hooks, LFS integrations and provider-specific receive-pack behavior require further compatibility validation.
