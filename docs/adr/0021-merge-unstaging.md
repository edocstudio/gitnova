# ADR 0021 — Unstage inside the active operation inspector

The graph already selects Working changes, but the operation inspector combined staged and unstaged paths into one result list. Reuse that inspector and diff dock: keep conflicts separate, show Unstaged and Staged groups, and place per-file Unstage and Unstage all changes on the staged group. These controls act on index membership and cannot be represented by commit selection alone. Review the exact scope in the existing composer before confirming; no new navigation or dialog.

Owned pending merge/cherry-pick/revert sessions support reviewed index-only unstaging against original HEAD. Working files, branch/HEAD and native operation metadata remain unchanged. Unresolved conflicts, hidden index entries and gitlinks require separate resolution/review. Prepare a temporary index, preserve the original raw index and pin its staged tree for recovery, revalidate under the native index lock, then publish atomically. Never use a whole-repository reset that clears MERGE_HEAD. Preview reads bounded staged code without running hooks or filters; large/binary contents need no raw-file backup because no working file is written. Unstaged diff selection compares index to working content. Restaging uses the existing reviewed working-result action. Finish explicitly includes staged content only.
