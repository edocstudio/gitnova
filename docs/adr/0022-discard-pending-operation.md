# ADR 0022 — Reviewed discard in an owned pending operation

Working changes already offers discard, but the operation inspector omitted it. Reuse its heading trash control and existing discard composer rather than introducing a screen or menu. Preview exact files and staged/unstaged scope, preserve recovery before writes, and explicitly state that discard keeps the operation pending. Abort remains a distinct existing action. No action runs on the user's live repository during development.

Ordinary discard continues to refuse active operations. Separate operation-scoped native commands require the current owned session token, no unresolved conflicts and unchanged native metadata. The same guarded discard engine preserves HEAD, branch, native operation metadata and staged content for unstaged-only scope. Full selected scope restores HEAD only for those leaves; it never runs reset/clean or clears MERGE_HEAD. Recovery retains raw index, selected working files and staged content. Large regular working files in this explicit context use bounded streaming hashing/copying rather than large in-memory buffers. New/untracked leaves are individually removed only after complete recovery and revalidation. Directories, gitlinks, hidden/sparse entries and unowned/conflicted operations require separate inspection. Partial application is reported honestly and never retried automatically.
