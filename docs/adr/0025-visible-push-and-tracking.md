# ADR 0025 — Visible Push and upstream comparison in graph context

The user requests a discoverable Push control and explicit local/upstream ahead/behind counts. Push already exists under Manage branch, but a hidden nested action does not expose the next everyday step after a merge. Reuse its existing destination/preview/confirmation flow: provide one current-branch Push entry beside the branch selector, and a direct Push entry on local refs in the existing graph menu. No new screen, panel or navigation is introduced.

Read local branches and configured upstream comparisons in one bounded native Git for-each-ref request, rather than spawning a process per branch. Keep this additional read outside low-level status/refs methods used repeatedly by write validation. Graph and working snapshot responses carry optional tracking metadata; write authorizations continue to use their own fresh validation. Counters describe commits relative to locally fetched upstream refs, not a live server promise, graph row count or changed-file count. Show unknown/missing-upstream/shallow states explicitly instead of fabricating zeroes. A later Fetch/Push or external ref update refreshes counts.

Use actual configured upstream and push destinations, including different remote/local branch names. Keep first-publication destination selection and optional upstream setting explicit. Preserve the existing live destination check, outgoing commit preview, no-force rules, pre-push hooks, partial-failure reporting and recovery. Never publish to a user's real repository as a development test.
