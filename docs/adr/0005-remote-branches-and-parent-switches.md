# ADR 0005: Remote branch selection and parent switches

Accepted, 2026-10-25. Implementation increment: remote browsing/fetch, reviewed fast-forward local integration, and nonrecursive parent branch switches.

Keep all actions in the existing branch picker attached to the graph. Add Local / Remotes scopes there, not a permanent sidebar or network dashboard. Remote names and cached branch refs are inspectable without network access. A remote with no cached refs has a per-remote Fetch action because an unknown branch cannot be selected from the graph. Selecting a remote branch explicitly fetches that branch, then presents the local effect in the existing confirmation area. No background network requests or batch pull.

A remote selection creates a matching local tracking branch, or switches to and fast-forwards that local branch. Already-ahead local history stays intact; divergence blocks integration. A conflicting upstream or branch checked out elsewhere blocks the operation. Network fetch and local integration are separate recorded operations; neither a sequence nor a batch is described as atomic. A failed integration retains fetched objects/refs and reports recovery without rollback/retry. Bind confirmation to local state, remote OID and remote/configuration snapshot; no network access occurs during preview or confirmation. Remote branches can change again on the server after fetch; the preview describes the fetched revision.

Fetch uses native Git authentication, selected configured remote names, explicit heads-only refspecs, no recursive submodule fetch, no tags/prune, no FETCH_HEAD overwrite and no configured extra refmaps. Standard file/HTTP(S)/SSH/Git transports are permitted; custom remote helper protocols are excluded. Preview never runs hooks or submodule custom update commands. Local integration is explicit fast-forward only, without auto-stash, force, reset, rebase or merge commits. Native hooks/filters can run during confirmed writes.

The original branch switch rejected every gitlink change. Permit reviewed 160000-to-160000 pointer changes while preserving submodule checkouts with nonrecursive Git operations. Display old/target/checked-out revisions and dirty state. Never initialize/update submodules here. Add/remove/type replacement still requires a dedicated workflow. Block staged work, ordinary dirty files, dirty submodule content and hidden index flags. Permit an unstaged gitlink mismatch only when the child repository itself is clean: this lets users switch back after the parent pointer changed, without moving or discarding child commits. Parent status honestly reports the retained checkout mismatch.

References: [Git switch](https://git-scm.com/docs/git-switch), [Git fetch](https://git-scm.com/docs/git-fetch), [Git merge](https://git-scm.com/docs/git-merge).
