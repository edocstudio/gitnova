# ADR 0018 — Reviewed discard in Working changes

Use the existing graph Working changes inspector and bottom diff. Add one contextual Discard… action to its heading and a file context menu for selected-path discard. Reuse the inspector for exact branch, selected file list and confirmation; no screen or dashboard. Stage and content inspection remain distinct. Default whole-change discard restores selected ordinary files and staging to HEAD; per-unstaged-file discard restores from the current index and preserves staging. Untracked selected files are removed only after recovery is durably saved. The scope is explicit and editable before confirmation.

A typed request carries exact registered relative native paths, scope and UUID. Read-only previews hash actual content, index, HEAD, configuration and directory identity, with complete bounded recovery preflight. Hidden/sparse entries, conflicts, directories, nested repositories and gitlinks are never recursively discarded. Submodules instead reuse the existing recorded-version preview beside their Working changes entry; show recorded, checked-out and parent HEAD pointers, distinguishing a pointer mismatch from dirty child content.

Execution uses the common operation guard and exclusive native index/HEAD/branch locks. Save private recovery under the shared common Git directory (so linked-worktree removal cannot delete it), with source checkout identity and raw working files/symlink targets, original index and selected staged blobs plus a complete manifest before any checkout. Prepare/restore through a temporary source-local index; unstaged discard never publishes it, while all-content discard publishes only reviewed selected index updates. Use fixed native Git restore path arguments without recursive submodule updates, force resets, clean, automatic stash or unrelated path writes. Confirmed configured filters may run; previews never execute them. Recheck original state and remaining files during execution. Report partial failures, retain recovery, and never retry or roll back automatically. Batch writes are not atomic against external editors; only one explicitly selected repository is affected.

Limits: 2,000 selected paths, 16 MiB per file/blob, 64 MiB working data and 128 MiB combined recovery, bounded Git subprocesses. No submodule child discard, directory cleanup, conflict reset or history movement. Native Windows/Linux behavior requires separate validation. See official [git restore](https://git-scm.com/docs/git-restore).
