# Milestone 55 — Device-wide Dark and Light themes

Settings → General now includes Theme alongside Language. Dark is the default when there is no saved preference; Light can be selected explicitly. The choice applies immediately, persists locally, and follows preference changes from other app windows. Blocked storage keeps a usable session preference. There is no polling, account dependency or Git mutation.

Existing CSS colors now use role-based surface, ink and edge tokens with their exact original dark colors as fallbacks. `theme-colors.css` supplies the corresponding light palette. Selected rows and tabs retain blue emphasis, diff additions/removals retain green/red backgrounds and text, and graph/author colors have theme-specific variants. This changes presentation rather than applying a rendered-screen inversion. Shared Settings, Connections, FAQ, forms, menus, history, diff and conflict surfaces use the palette.

Validation: TypeScript and 43 frontend unit tests passed. Focused real-core browser tests covered FAQ and theme selection; the theme regression verifies Dark default, Light persistence after reload, unchanged Git state, preserved commit draft and selection, and a return to Dark. Five sampled Light text/background pairs (commit subject, date, inspector heading, added code and removed code) met 4.5:1 contrast. The populated Light graph/diff screenshot was visually inspected. Browser transport is emulated; fixtures are real temporary repositories. This does not certify every visual state, native OS dialog appearance, native clipboard behavior or other operating systems.
