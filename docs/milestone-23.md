# Milestone 23 — Recorded activity after restart

Everyday use needs a way to revisit an operation result and its recovery location after the window or machine restarts. Durable receipts already existed; this change exposes bounded read-only summaries in a collapsed section of the existing Working changes inspector. No new navigation or synthetic commit rows are introduced. ADR 0020 records the surface rationale and bounds.

The native-independent core scopes receipts to RepositoryId, includes linked worktree identity, retains started/unknown outcomes as unconfirmed and reports incomplete inspection. Original receipts remain unchanged. Recovery pointers are copied as recorded data; they are not followed, executed or certified complete. No retry, lock removal, automatic restore or claim of current Git state is added. The UI uses both English and Thai catalogs and clears previous results when loading another checkout.

Core tests use actual temporary repositories: a reviewed discard survives Application recreation with the same retained raw content/location; history preserves index/catalog/files; linked checkout records are included while another repository is excluded; unconfirmed receipts and native lock files are untouched; malformed/oversized records and scan limits report incomplete coverage; symlink files are skipped and a symlink journal directory is refused. Browser acceptance reloads after an actual discard and finds the recorded recovery path through the existing inspector. Native IPC coverage includes trusted command serialization and remote-origin rejection.

Validation: four core integration tests passed, twenty frontend unit/catalog tests passed, and the recorded discard workflow passed after reload and EN→TH switching. The broader serial browser acceptance also passed commit/pull/push/merge, cross-branch stash/pop, workspace switching, worktree creation/removal and submodule initialization/restoration. The focused strict core Clippy and workspace format checks passed. The native IPC dispatch/origin test and final local packaging plus actual hidden WebKit/single-instance smoke also passed. See the [focused daily-use acceptance report](verification/2026-10-27-daily-use.md) for the scope and practical limits. This feature is inspection of existing receipts, not automated crash recovery. Atomicity, stale locks, external Git writes and missing/deleted backup files still need practical inspection.
