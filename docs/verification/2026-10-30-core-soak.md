# Persistent-core large-repository soak — 2026-10-30

## Protocol and provenance

Measured the current alpha core using a persistent Application instance, real temporary Git fixtures, one shared object database and three worktree locations: 50,000 commits and 10,001 tracked files. Graph includes selected-commit detail; snapshot reads working state; metadata search and file/code investigation use workspace scope. Comparison uses main → release. No builds or tests ran during sampling. The normal native app remained open; its memory is excluded and other applications can affect latency.

Executable SHA-256: `42403dd740fbf09f692f2e2107ea6e57eb4f8729a07d6366bee190af7ff2081d`. Base source commit: `8a0916a682b0ad4edf4d5e9ce951bc38c6545b47`; uncommitted changes: `True`. This is a local debug probe with first-party CPU crates at optimization level 2, not a signed/notarized release benchmark.

The workload completed in **1810.24 seconds**, 128 cycles and 768 operation calls. Total wall time including setup/cleanup: 1821.53 seconds. The final probe check confirmed unchanged HEAD and no staged/unstaged/untracked changes in each checkout; it does not compare every configuration, ref or index byte.

## Sampled resident memory

Collected 356 samples at nominal five-second intervals. Largest observed gap: 5.259 seconds. Workload peak core RSS: **55.95 MiB**. Peak sampled core + descendant RSS: **85.39 MiB**. The native UI/WebKit is excluded.

The final window is short. The observed RSS did not increase continuously in this repeated fixed-fixture workload. RSS changes can reflect allocation, paging or compression and do not diagnose leaks. No resource guard fired. A 30-minute core run does not establish full-workday app stability, high-churn independent-repository cache behavior, large binary-diff recovery costs or foreground WebView performance.

The first short probe stopped on a benchmark-fixture assertion: the chosen phrase occurred once in every revision, so literal occurrence-count search correctly returned no changes within its recent window. The harness now separates path history and a specific introduced phrase. That failed preparation probe is excluded from all measurements above.

No before/after, cross-product or language-level speed advantage is established by these measurements. Hosted OS/native distribution checks and a new full native/UI soak remain separate work.

“Cold” means the first observation in the new Application instance, not an OS
filesystem-cache flush. Warm calls cycle through registered checkout locations.
The fixture was just created, so kernel filesystem caches may already be warm.

After the measured run, the Python runner was hardened to discard inherited
Git override variables for both the synthetic workload and source-provenance
reads. A 60-second/2,000-commit/501-file smoke with deliberately nonexistent
GIT_DIR/GIT_WORK_TREE targets passed and left both sentinel paths absent. The
first isolation smoke found that the provenance commands had not yet received
the sanitized environment; this reporting-only path was corrected and rerun.
The 30-minute measured JSON is unchanged; its environment had no repository
redirect overrides (only GIT_PAGER), and its recorded executable hash is retained.
