# Read-only Local MCP verification — 2026-11-11

## Scope and architecture

Implemented an optional executable, `gitnova-mcp`, using official `rmcp =3.9.0`
(server and stdio only). The adapter calls `gitnova-core::local_analysis`, which
uses the desktop application's existing `gitnova-git::GitCli` executor. There is
no second Git engine, HTTP listener, model API, embedded chat, daemon, write tool
or arbitrary shell tool.

Workspace/recent state is deliberately not shared as authorization. A separate
operator allowlist grants exact checkout identities; tool inputs use opaque IDs.
Policy is reloaded and identities revalidated on every call and before delivery.
No new UI is needed for this MVP. Operator permission commands are outside the
MCP tool surface. See [setup and limits](../mcp/local-server.md).

Available tools: `list_repositories`, `get_status`, `get_diff`,
`search_commits`, `get_line_history`, `get_conflict_summary`.

## Exercised boundaries

- Actual executable initialize, tools/list and calls to all six tools; JSON-RPC
  only on server stdout, unknown tools/fields/types/nulls/ranges rejected.
- Default deny, unknown repository, malformed policy, live permission updates
  and revocation without restarting the server.
- Unborn, clean/dirty, staged and unstaged content, detached HEAD, real conflicts,
  linked worktrees and explicit child-repository grants.
- Path traversal, absolute Windows paths, symlinks on macOS, nested independent
  repositories, uninitialized gitlinks and replacement repository identity.
- Committed line attribution stays distinct from local edits; invalid revision
  expressions/dates rejected; literal filenames include spaces/brackets/dashes.
- Binary summary, large patches, bounded output, per-file omissions and correct
  next offset when the byte budget ends before the page limit.
- Recognizable secrets/private-key material reduced or omitted; configured
  clean/process filter, external diff, textconv and fsmonitor traps not executed.
- HEAD, branch refs, index bytes and working files preserved by analysis.
- MCP cancellation kills/reaps an intentionally slow task-owned Unix Git process;
  client disconnect terminates the server within the bounded shutdown check.

## Unverified and remaining limitations

- No Windows/Linux execution, OS-specific filesystem security or process cleanup
  validation was performed for this addition. Existing CI workspace discovery
  includes the new crate, but no remote CI run was triggered in this task.
- No interactive Codex/Claude session or other client surface was launched.
  Configuration syntax was checked against the official
  [Codex guide](https://developers.openai.com/codex/mcp) and
  [Claude Code guide](https://code.claude.com/docs/en/mcp).
  SDK selection was verified against the official
  [Rust SDK](https://github.com/modelcontextprotocol/rust-sdk) and
  [rmcp documentation](https://docs.rs/rmcp/3.9.0/rmcp/).
- The debug executable was built and exercised. No release-profile build,
  installer, desktop GUI end-to-end test, benchmark or soak run was performed.
- Allowlist checks are not an OS sandbox and cannot make hostile concurrent
  filesystem replacement atomic. Keep Git and the configuration directory trusted.
- Redaction is heuristic and incomplete. Cloud-model clients may transmit results
  outside the machine. No claim of exhaustive secret detection is made.
- Offset pagination reads live state. Returned HEADs detect history movement,
  not every concurrent working-file/index edit. Shallow history is incomplete.
- Status excludes submodule entries; approve/query children separately. Large
  files/metadata and unsupported encodings may return omissions or bounded errors.
- Inventory gaps remain; collecting SDK license texts is not complete license
  compliance or a shipping-artifact audit.

No real repository was authorized for MCP, no client configuration was edited,
and no commit, push, PR, release, publish or deployment was performed.
