## Practical limits

Pull integrates only by fast-forward; diverged branches require the explicit merge workflow. Stash can be popped onto the current branch; stash conflicts currently require Git inspection/resolution. Large patches and changed-file lists have explicit budgets. Read-only recorded activity exposes historical outcomes and recovery pointers after restart; it does not remove locks, replay interrupted writes or guarantee missing backup data can be restored.

Clone, rebase/amend, partial-hunk and stage-all actions, submodule add/remove/URL sync/remote-branch update, worktree repair/unlock/prune, file/code archaeology and release intelligence remain outside the current implementation. Workspaces can contain multiple existing repositories, but context restoration is currently in-memory rather than durable graph scroll/selection across restarts.

The cause of the earlier machine freezes remains unconfirmed. Verification is intentionally serial with one compiler job or one browser worker; background endpoint scanning was observed during diagnostics. No endpoint protection or OS security settings were changed.

Before relying on a remote-specific flow tomorrow, verify it with the intended credentials and a disposable branch. Unconfirmed/partial outcomes must be inspected before retrying. Public signing/notarization, optimized release validation and Windows/Linux runtime validation remain separate work.
